# Embodied AI learning log | 具身智能学习与实验记录

我近期围绕机器人推方块任务，完成了从强化学习基线复现，到跨机器人示范迁移的两阶段实践。这里记录实际运行、评估协议、失败分析与下一步问题。结果均来自仿真中的状态观测，尚未涉及视觉策略或真实机器人。

## 项目一：ManiSkill PushCube PPO 复现（2026-10）

- 使用官方 PPO 基线，在 RTX 4090 上完成约 196.6 万步、单个训练种子的 PushCube-v1 训练。
- 自建 100 个固定种子、50 步的独立评估：训练前成功 0/100；训练后曾达到目标 90/100，回合结束仍成功 78/100。
- 保存逐回合数据、学习曲线与轨迹录像；发现 12 个回合达到目标后又离开，提出训练成功即重置与固定时长评估之间的差异作为待验证假设。
- [代码与完整记录](../pushcube-ppo-open/README.md)（本地；GitHub 发布待认证）。

## 项目二：Franka → UR5 的 PushCube 示范迁移（2026-10）

- 构建 Panda 与 UR5 推杆的仿真任务、示范采集与重放管线，记录 1200 条 Panda 成功轨迹和 20 条 UR5 成功轨迹。
- 实现精简状态 ACT，完成 3 个训练种子 × 4 个源数据规模（0/100/500/1000）的 12 次正式运行，以及 2 次追加诊断；每次独立测试 200 个初始状态。
- 检查控制方向、频率、轨迹可执行性与关节限位；1194 条抽样并集重放均被接受。
- 同预算比较中未观察到正迁移：UR5-only 三个种子的最终成功率为 97%、0%、46.5%，混入源轨迹的各组均为 0%。目标样本曝光量和收敛不稳定性是后续需要控制的因素，现有诊断不能确定单一根因。
- [代码、配置和完整实验记录](../franka-ur5-pushcube-act/README.md)（本地；GitHub 发布待认证）。

## 我学到的研究习惯

1. 将训练指标与独立评估分开，明确“曾成功”和“最终成功”的区别。
2. 对照实验要固定随机种子、测试初态和训练预算，并报告每个种子的结果。
3. 记录失败运行、代码来源、配置与数据清单；对于负结果继续做动作语义和数据曝光量诊断。
4. 把相关性和因果解释分开，避免把单种子仿真结果外推到真实机器人。
