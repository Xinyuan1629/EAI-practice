我近期围绕机器人推方块任务，完成了从强化学习基线复现，到跨机器人示范迁移的三条实践线。这里记录实际运行、评估协议、失败分析与下一步问题。结果均来自仿真中的状态观测，尚未涉及视觉策略或真实机器人。

- 使用官方 PPO 基线，在 RTX 4090 上完成约 196.6 万步、单个训练种子的 PushCube-v1 训练。
- 自建 100 个固定种子、50 步的独立评估：训练前成功 0/100；训练后曾达到目标 90/100，回合结束仍成功 78/100。
- 保存逐回合数据、学习曲线与轨迹录像；发现 12 个回合达到目标后又离开，提出训练成功即重置与固定时长评估之间的差异作为待验证假设。
- 完整代码与记录位于本地 `Projects/pushcube-ppo-open/`，待 GitHub 发布。

## 项目二：Franka → UR5 的 PushCube 示范迁移（2026-10）

- 构建 Panda 与 UR5 推杆的仿真任务、示范采集与重放管线，记录 1200 条 Panda 成功轨迹和 20 条 UR5 成功轨迹。
- 实现精简状态 ACT，完成 3 个训练种子 × 4 个源数据规模（0/100/500/1000）的 12 次正式运行，以及 2 次追加诊断；每次独立测试 200 个初始状态。
- 检查控制方向、频率、轨迹可执行性与关节限位；1194 条抽样并集重放均被接受。

- 完整代码、配置和记录位于本地 `Projects/franka-ur5-pushcube-act/`，待 GitHub 发布。

## 项目三：ContactExplorer 灵巧操作复现与分析（2026-10）

- 阅读论文与官方 Isaac Gym 实现，拆解接触覆盖计数、能量引导奖励和 PPO 训练流程；选取 LEAP 手的 CubeInBox 任务做单任务复现。
- 跑通 64 环境训练、2048 环境容量测试、独立评估和 JSON 导出；随后完成单训练种子的 ContactExplorer 与移除探索奖励的 PPO 对照，并开展接触覆盖、摩擦扰动等后续评估。
- 固定策略的独立评估中，ContactExplorer 在 1250 更新的两个 nominal 评估种子分别为 373/384（97.14%）和 359/384（93.49%）；2000 更新的两个 nominal 评估种子分别为 333/384（86.72%）和 312/384（81.25%）。对应 baseline 的 2000 更新 nominal 评估均为 0/384。
- 这些是同一训练种子下对固定 checkpoint 的评估，评估种子不能替代独立训练种子；也不等于复现论文的全任务、多种子或真实机器人结论。
- 原始官方代码和本地复现记录位于 `~/ContactExplorer-reproduction/`；个人实验结果仍是未跟踪文件，公开前需要单独整理，不能把上游仓库直接当作个人原创项目。

## 我学到的研究习惯

1. 将训练指标与独立评估分开，明确“曾成功”和“最终成功”的区别。
2. 对照实验要固定随机种子、测试初态和训练预算，并报告每个种子的结果。
3. 记录失败运行、代码来源、配置与数据清单；对于负结果继续做动作语义和数据曝光量诊断。
4. 把相关性和因果解释分开，避免把单种子仿真结果外推到真实机器人。
